# IT Strategy and Operating Model

The IT Operating Model defines how technology services will be delivered, managed, and governed to support business operations.

---

## What is an IT Operating Model?

The operating model describes:
- How IT services are delivered
- Who does what (roles and responsibilities)
- How work flows through the organisation
- How decisions are made
- How performance is measured

---

## Key Components

| Component | Description |
|-----------|-------------|
| **Service catalogue** | What services IT provides |
| **Organisation structure** | Teams, roles, reporting lines |
| **Processes** | How work gets done (ITIL, etc.) |
| **Governance** | Decision-making and oversight |
| **Sourcing model** | In-house, outsourced, hybrid |
| **Tools and technology** | Enabling platforms |
{:class="table table-single table-narrow"}

---

## Operating Model Dimensions

| Dimension | Considerations |
|-----------|----------------|
| **People** | Skills, capabilities, culture |
| **Process** | Workflows, procedures, standards |
| **Technology** | Tools, platforms, automation |
| **Partners** | Vendors, suppliers, outsourcers |
| **Governance** | Controls, policies, compliance |
{:class="table table-single table-narrow"}

---

## Sourcing Options

| Model | Description | When to Use |
|-------|-------------|-------------|
| **In-house** | Internal teams deliver all services | Core capabilities, strategic control |
| **Outsourced** | External providers deliver services | Non-core, cost efficiency |
| **Hybrid** | Mix of internal and external | Balance of control and flexibility |
| **Managed service** | Provider manages specific functions | Specialist capabilities |
{:class="table table-single table-narrow"}

---

## Design Considerations

- Business strategy and requirements
- Current capabilities and gaps
- Cost and efficiency targets
- Risk appetite
- Market availability of skills
- Regulatory requirements

## Aligning with IT Strategy

IT strategy alignment makes sure the project's technology decisions support the organisation's wider technology direction and enterprise architecture.

### Purpose

Aligning with IT strategy:
- Ensures technical decisions support long-term goals
- Avoids creating technical debt
- Enables integration with existing systems
- Supports enterprise architecture standards
- Maximises return on technology investment


### Key Considerations

| Area | Questions to Address |
|------|---------------------|
| **Architecture fit** | Does the solution align with enterprise architecture? |
| **Technology standards** | Are approved technologies being used? |
| **Integration** | How does it connect with existing systems? |
| **Data** | How does it align with data strategy? |
| **Security** | Does it meet security requirements? |
| **Cloud strategy** | Does it align with cloud adoption plans? |
{:class="table table-single table-narrow"}


### Common IT Strategy Elements

| Element | Description |
|---------|-------------|
| **Technology roadmap** | Planned technology evolution |
| **Architecture principles** | Guiding rules for technology decisions |
| **Standards catalogue** | Approved technologies and platforms |
| **Integration patterns** | How systems should connect |
| **Security policy** | Security requirements and controls |
{:class="table table-single table-narrow"}


### Alignment Activities

1. **Review enterprise architecture** - Understand current state and direction
2. **Engage architecture team** - Get guidance on technology choices
3. **Document deviations** - Justify any departures from standards
4. **Plan for compliance** - Include activities to meet standards
5. **Consider future state** - Design for strategic direction
